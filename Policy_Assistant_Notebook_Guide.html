Policy Assistant Notebook

A plain-English walkthrough of every cell in Company_Policy_Assistant_RAG.ipynb — what it does, why it's there in that order, and how to fix it when a cell misbehaves.

8 code cells 2 scripts — build_index.py & app.py 0 agents or tools — plain retrieve → augment → generate Free to run — no API key, fully local

The idea in one sentence

Every question goes through the exact same three steps, in the exact same order — nothing decides anything.

01 · RETRIEVE

Search the PDF

retrieve_context(vector_db, question, k=3)

Finds the 3 chunks of company_policy.pdf whose meaning is closest to the question.

02 · AUGMENT

Build the prompt

ask_llm(llm_pipeline, context, question)

Pastes those 3 chunks and the question into one prompt, alongside the system rules.

03 · GENERATE

Ask the LLM

llm_pipeline(messages, ...)

A local Hugging Face model (Qwen2.5-1.5B-Instruct) answers using only the pasted policy text — no API, no key.

How the two scripts connect

build_index.py runs once and writes a searchable index to disk. app.py runs on every question and only ever reads that index — it never re-opens the PDF.

Cell by cell

Run these in order, top to bottom. Colab clears its files whenever the runtime disconnects, so a fresh session means re-running from Cell 1.

Saves the chat app — the retrieve → augment → generate logic, with no agent deciding steps. The LLM itself (Qwen2.5-1.5B-Instruct) downloads automatically the first time it runs.

Starts the app in the background on port 8501, inside the Colab machine. The first question is slow — that's the local model loading — then it stays warm for the rest of the session.

When something breaks

"Couldn't find the 'faiss_index' folder"
Cell 4 didn't finish, or the runtime restarted since it ran. Re-run Cells 3 and 4 before touching the app again.
Tunnel link won't load
Streamlit (Cell 6) may still be starting — wait ~10 seconds and refresh, or run !cat /content/logs.txt to see the actual error.
Tunnel URL changed since last time
Expected — every run of Cell 7 prints a new link. Share the newest one, not an old one from an earlier session.
Answers take 30–90 seconds, app looks frozen
Normal on a free CPU runtime — the model is generating token by token with no GPU. For much faster answers: Runtime → Change runtime type → T4 GPU, then re-run from Cell 1.
Session crashes / "out of memory" while loading the model
The free CPU runtime occasionally runs low on RAM for the model download. Runtime → Restart session, then re-run from Cell 1 — a GPU runtime usually has more headroom too.

Terms used above

Chunk
A ~500-character slice of the PDF. Small enough to search precisely, large enough to keep context.
Embedding
A list of numbers that captures what a chunk of text means, so "similar meaning" becomes "nearby numbers."
FAISS index
A file on disk holding every chunk's embedding, built for fast "find the closest ones" search.
Similarity search
Comparing the question's embedding against every chunk's embedding and keeping the top 3 matches.
System prompt
Standing instructions sent with every question — here, "only answer from the text I give you."
Tunnel
A temporary public URL that forwards to the Streamlit app running inside the private Colab machine.
HF pipeline
Hugging Face's transformers.pipeline(...) — downloads a model and runs it locally, no API or key. What Cell 5's app.py uses to generate answers.
